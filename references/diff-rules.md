# 双表核对判定规则

本文件是技能执行时必须遵守的硬性判定知识，按需加载。核心是把「看起来像差异」和「真的是差异」分开，并让结果可复算。

## 一、三态空值区分（最重要的坑）

CSV 里一个单元格至少有三种语义，混为一谈会得出错误结论：

| 状态 | 含义 | 报告中展示 | 与 `0` 的关系 |
|---|---|---|---|
| 缺失 | 该列在表中根本不存在 | `(缺失)` | 与 `0` 不同 |
| 空字符串 | 列存在但值为空（CSV 里两个逗号之间没有内容） | `(空字符串)` | 与 `0` 不同 |
| 有值 | 列存在且值非空 | 原始内容 | `0` 属于有值 |

**判定规则：**
- 两侧都是 空字符串 / 缺失 → 视为一致，不报差异。
- 一侧 空字符串/缺失、另一侧 有值 → 报「状态不同」，不进数值容差比较。
- 一侧 缺失、另一侧 空字符串 → 视为不同状态，报「状态不同」（列结构不一致的信号）。
- 数值 `0` 永远是「有值」，与空字符串的差异必须被报出，绝不能静默填 `0`。

## 二、重复键处理

「重复键」指同一个匹配键在**同一张表内**出现不止一次。

- 重复键**必须单独成节列出**，展示每次出现的行号与整行内容。
- **绝不静默取第一条**或自动合并——取错行会让对账结论失真。
- 含重复键的键不参与 1:1 比对，整体移入「需你确认的 / 重复键」节，待用户确认归属后再核对。
- 重复键常意味着上游导出重复、JOIN 膨胀或主键选错，要在报告里点明。

## 三、数值比对用容差，不用等号

- 浮点 / 金额比较一律用容差：`abs(B - A) <= 容差` 视为一致。默认容差 `0.01`，用户可改。
- 容差只对**两侧都能解析为数字**的单元格生效；一侧非数字则退回文本精确比较。
- 差值统一展示为 `B - A`，并在报告写清容差，保证他人能复算。
- 不要用字符串相等判断数值（"100.00" 和 "100" 是同一个数，但文本不同）。

## 四、仅 A 有 / 仅 B 有

- 以匹配键集合的差集判定：在 A 不在 B = 仅 A 有；反之 = 仅 B 有。
- 这两类不进数值比对，直接列出键与关键列快照，供用户判断是漏数还是新增。

## 五、可复算说明（结果可信的关键）

每份报告末尾必须给出：
- 复现命令（含文件路径、--key、--cols、--tolerance、--ignore-case 等完整参数）
- 参与比对的唯一键数、容差、是否忽略大小写、是否去空格
- 声明「只读不写，未修改原文件」

没有可复算说明的核对报告，用户无法向他人证明结论正确，技能价值减半。

## 六、列名不一致时的处理

- A、B 列名不同（如 `user_id` vs `uid`）→ 停下来请用户确认对应关系，**不猜测映射**。
- 用户确认后，在报告里写出映射对照，再比对。
- 脚本 `--key` 要求列名已在两表存在；若列名确实不同，先让用户重命名或明确对应关系。
